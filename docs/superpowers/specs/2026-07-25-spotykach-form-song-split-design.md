# Spotykach FORM / SONG Split

**Date:** 2026-07-25
**Status:** Approved design and written spec
**Scope:** PITCH lanes in STEP mode, the VCV PLAY row, patch migration, and
tests. This document supersedes the FORM-control and fixed-form portions of
`2026-07-24-spotykach-song-pattern-chaining-design.md`.

## 1. Purpose

The first song-pattern implementation combines two different concepts in the
VCV `FORM` knob:

- five phrase-generation engines; and
- the larger `AAAB` arrangement.

These become independent controls:

- `FORM` chooses how phrases are composed;
- `SONG` chooses when persistent Phrase A or Phrase B is played;
- `MELODY` remains solely responsible for evolving the phrase that just
  completed.

The factory combination is `FORM = HIERARCHICAL` and `SONG = AAAB`.

## 2. Musical model

Every melodic STEP lane owns two persistent full-pattern snapshots:

- Phrase A is generated by the selected FORM engine;
- Phrase B is derived once from A as a related variation with a distinct
  turnaround, using the derivation rules in the original design.

FORM has five snapped values:

1. `TWO MOTIFS`
2. `ONE + VAR`
3. `HIERARCHICAL`
4. `CALL / RESPONSE`
5. `OSTINATO`

SONG has seven snapped values:

1. `AAAB`
2. `ABAB`
3. `ABBB`
4. `BUILD`
5. `ROTATE`
6. `MIRROR`
7. `OFF`

SONG only selects A or B. It does not mutate pitches, gates, groove ranks, note
lengths, or motif metadata, and it consumes no random draws.

## 3. SONG sequences

Let `i` be the zero-based count of phrases since the current SONG arrangement
was started or reset. `A` is snapshot 0 and `B` is snapshot 1.

### 3.1 Fixed forms

The fixed forms repeat every four phrases:

```text
AAAB: A A A B
ABAB: A B A B
ABBB: A B B B
```

### 3.2 BUILD

BUILD repeats this 16-phrase arc:

```text
AAAB · AABB · ABBB · AABB
```

It moves from a stable A statement toward B dominance, then releases to the
balanced middle state before restarting.

### 3.3 ROTATE

ROTATE repeats this 16-phrase cycle:

```text
AAAB · AABA · ABAA · BAAA
```

The single B turnaround moves one phrase earlier in each four-phrase group.

### 3.4 MIRROR

MIRROR uses the Thue-Morse sequence. The selected symbol is B when the number
of set bits in `i` is odd and A when it is even:

```text
ABBA · BAAB · BAAB · ABBA · …
```

This is deterministic and non-periodic without storing a long sequence or
using randomness.

### 3.5 OFF

OFF selects Phrase A for every phrase index:

```text
AAAA · AAAA · AAAA · …
```

It disables only A/B arrangement. Phrase A continues to evolve under MELODY.
Phrase B remains allocated and unchanged during OFF playback, so returning to an
active SONG mode does not require regeneration. FORM, NEW, and effective STEPS
changes still rebuild both A and B while OFF is selected.

## 4. Boundary lifecycle

All structural changes remain boundary-safe. A write during a phrase becomes
audible at the next STEP phrase wrap, and the final write before that boundary
wins.

At a normal wrap:

1. apply RENEW or GROW to the outgoing A or B snapshot;
2. retain that snapshot-local mutation;
3. apply pending FORM, SONG, NEW, or effective STEPS work;
4. select the incoming A/B symbol;
5. make its step 0 boundary audible.

The controls have distinct effects:

- **FORM change:** generate a fresh A with the selected phrase engine, derive a
  fresh B, clear phrase-evolution state as a fresh phrase does today, and reset
  SONG to phrase index 0.
- **SONG change:** retain A and B unchanged and reset only the SONG phrase index
  to 0.
- **NEW:** generate a fresh A and B with the current FORM and reset SONG to
  phrase index 0.
- **Effective STEPS change:** rebuild A and B at the new length and reset SONG
  to phrase index 0.
- **MELODY change:** does not reset SONG.

Combined pending work coalesces into one transition. FORM and STEPS establish
the generator and length, NEW requests the fresh pair, and the final SONG value
selects the arrangement that starts at index 0. A SONG-only change must not
consume RNG or alter either snapshot.

Before the first audible STEP, factory or restored FORM and SONG values apply
without emitting a phrase from an obsolete mode.

FLOW continues to pause the SONG phrase index and both snapshots. Returning to
STEP resumes the stored position. Non-melodic lanes do not execute SONG
behavior.

## 5. Engine boundaries and API

The existing `Principle` values remain the internal phrase-engine choices. The
mixed `FormMode`, whose first entry is currently `SongAAAB`, is replaced by a
dedicated song enum:

```cpp
enum class SongMode : uint8_t {
    AAAB = 0,
    ABAB,
    ABBB,
    Build,
    Rotate,
    Mirror,
    Off,
    kCount
};
```

`SongForm` continues to own the two `MelodyPattern` snapshots and turnaround
binding state. It additionally owns:

- selected and pending `Principle`;
- selected and pending `SongMode`;
- pending flags;
- a `uint32_t` phrase index.

The former four-position `form_position` is no longer sufficient because BUILD,
ROTATE, and MIRROR span or exceed one four-phrase group.

A pure allocation-free helper
`song_symbol_at(SongMode mode, uint32_t phrase_index)` implements all seven
sequences. Fixed modes use four-symbol lookup tables, BUILD and ROTATE use
16-symbol lookup tables, MIRROR computes bit parity, and OFF always returns 0.
It returns only 0 or 1 and never reads mutable lane state.

The portable API exposes clamped setters and observability for both dimensions:

```cpp
void set_form(int part, int form);
void set_song(int part, int song);
int form(int part) const;
int song(int part) const;
```

`set_form` maps `0..4` directly to the five `Principle` values.
`set_principle` remains as a source-compatible wrapper. Invalid integers clamp
to the nearest valid value. The render-scenario host gains `set_song`; existing
`set_form` and `set_principle` actions continue to work.

The implementation remains fixed-size POD with no heap allocation. The existing
whole-instrument ARM/Daisy size check retains its 5 KiB maximum delta from the
pre-song baseline.

## 6. VCV panel

The PLAY row becomes:

```text
STEP · FORM · SONG · NEW
```

For Part A, left to right:

- FORM remains at the current FORM position;
- SONG occupies the current NEW position;
- NEW moves to the current outer TRIG position.

Part B mirrors the same geometry. TRIG disappears from the faceplate.

Parameter IDs remain stable in count and per-Part stride:

- the existing `PRINCIPLE_A/B` slots become the five-value FORM parameters;
- the existing `TRIGGER_A/B` slots become the seven-value SONG parameters;
- `NEWPHRASE_A/B` retain their IDs but move geometrically to the former TRIG
  coordinates.

Internal enum names may be updated from `PRINCIPLE` and `TRIGGER` to `FORM` and
`SONG` only if their numeric positions remain unchanged. The generated panel,
factory parameter table, static stride checks, automation names, and tooltips
must agree.

Factory defaults for both Parts are:

```text
FORM = HIERARCHICAL
SONG = AAAB
NEW  = released
```

The VCV TRIG BooleanTrigger state and its call to `trigger_manual()` are removed.
The portable engine's manual-trigger capability may remain for other hosts.

NEW has one coherent meaning across engines:

- it always queues a fresh A/B phrase pair and resets SONG;
- on a Sampler Part it additionally punches the sampler immediately, returning
  to ORGANIZE and spawning a grain.

Thus removing TRIG does not remove the Sampler's immediate-grain gesture.

## 7. Patch persistence and migration

FORM and SONG are ordinary Rack parameters and are saved by Rack. The current
SONG phrase index and generated A/B contents are runtime state and are not
serialized. Patch load begins the selected SONG at phrase index 0, consistent
with the existing non-serialized phrase buffers.

New saves include a small format marker such as `"formSongVersion": 1`.
When the marker is absent, the loader performs a one-time migration:

1. read `lastBasis` from the first song-pattern beta when present;
2. otherwise read the released plugin's `principle` array when present;
3. otherwise use `HIERARCHICAL`;
4. write that value into the new FORM parameter;
5. force the new SONG parameter to `AAAB`.

This prevents the former momentary TRIG value from becoming an unintended SONG
selection and preserves the user's most recently selected phrase engine. New
saves stop writing `lastBasis` and `principle`, but the loader retains their
legacy readers.

Factory reset restores `HIERARCHICAL / AAAB` and clears pending structural work.

## 8. Determinism and edge rules

- SONG selection and advancement consume no RNG.
- MIRROR depends only on bit parity of the phrase index.
- OFF always selects A; it does not bypass snapshot storage or phrase evolution.
- A SONG-only change cannot change A/B bytes.
- Pending changes never switch snapshots mid-phrase.
- `process()` and `tick()` share the same boundary helper and select the same
  symbol.
- Phrase index wrap is defined by normal unsigned `uint32_t` wrap; MIRROR remains
  deterministic, and practical sessions cannot reach the wrap at musical
  phrase rates.
- VCV exposes STEPS `2..16`; the portable lane remains safe for `1..32`.
- FORM and SONG inputs are clamped at the public API boundary.

## 9. Verification

### 9.1 Helper tests

- Exact repeated sequences for AAAB, ABAB, and ABBB.
- Exact 32-phrase output for two BUILD and ROTATE cycles.
- Exact first 64 MIRROR symbols and bit-parity agreement across representative
  large indices.
- Exact OFF output of A across representative small and large indices.
- SONG clamping maps negative integers to AAAB and oversized integers to OFF.
- No RNG consumption by symbol lookup or advancement.

### 9.2 Lane and instrument tests

- Factory HIERARCHICAL/AAAB produces the existing persistent-AAAB behavior.
- A FORM change rebuilds A/B only at a wrap and resets SONG.
- A SONG change occurs only at a wrap, preserves A/B byte-for-byte, consumes no
  RNG, and starts at its first symbol.
- NEW and STEPS rebuild once and reset SONG.
- Final FORM/SONG writes win when several arrive inside one phrase.
- RENEW and GROW mutate only the outgoing snapshot before advancement.
- LOOP repeats every finite sequence bit-identically; MIRROR follows its exact
  deterministic stream; OFF plays only A while A retains ordinary outgoing
  MELODY evolution.
- FLOW pauses and resumes arrangement state.
- `process()` and `tick()` remain observably equivalent.
- Both Parts advance independently.
- The existing normal-mode golden check is replaced or reframed around the
  phrase-engine output before arrangement, while the factory
  HIERARCHICAL/AAAB render remains deterministic.

### 9.3 VCV and migration tests

- Generated geometry and labels are exactly `STEP · FORM · SONG · NEW`.
- FORM is a snapped five-value control with the approved names.
- SONG is a snapped seven-value control with the approved names.
- NEW occupies the old TRIG coordinate and remains a button.
- Param count, numeric IDs, and Part stride do not change.
- TRIG processing and BooleanTrigger state are absent.
- NEW always queues `new_phrase`; Sampler NEW additionally calls
  `sampler_punch`.
- Factory defaults are HIERARCHICAL/AAAB.
- Released `principle` JSON and beta `lastBasis` JSON both migrate to FORM while
  SONG becomes AAAB.
- New-format save/reload preserves FORM and SONG without re-running legacy
  migration.
- The VCV plugin builds, installs, and passes the panel guard.

### 9.4 Listening pass

At 16 STEPS and LOOP, audition all seven SONG positions with
FORM=HIERARCHICAL. Confirm that:

- the three fixed forms are immediately recognizable;
- BUILD increases and then releases B dominance;
- ROTATE moves the turnaround earlier by one phrase per group;
- MIRROR feels structured but avoids a short loop;
- OFF repeats A without selecting B;
- every transition occurs cleanly at a phrase boundary;
- NEW restarts each form from its opening;
- Sampler NEW still spawns immediately.

## 10. Non-goals

- Pattern identities beyond A and B.
- Random or probability-based SONG modes.
- SONG changing phrase content.
- SONG behavior in FLOW or non-PITCH lanes.
- Saving generated A/B note data or the live phrase index.
- A separate SONG-variation amount.
- Hardware control mapping or firmware UI changes.
- Replacing manual-trigger facilities outside the VCV panel.
