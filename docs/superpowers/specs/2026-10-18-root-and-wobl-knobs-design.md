# ROOT per deck and WOBL — the reserved knobs become parameters

Date: 2026-10-18. Status: approved by Bastian 2026-10-19; plan
`docs/superpowers/plans/2026-10-19-root-and-wobl-knobs.md`.
Follows: spec 2026-10-07 (nine-mm raster) §4, roadmap entry "Reserved knobs
become parameters".

## 1. Intent

The 9 mm panel pass put three small pots on the plate and the Rev A board that
send nothing: `ROOT_A`, `ROOT_B` and `REV_MOD` (caption WOBL). This round makes
all three real parameters, on the hardware panel, in the firmware, and in the big
VCV module `Fireflow` as well.

- **ROOT** picks each deck's key. Today `P_ROOT` is one global engine parameter
  that no host ever sets, so both decks always play in C.
- **WOBL** is the reverb's tail-delay LFO depth. The parameter exists and works;
  today the control law pins it to `0.15f`. Bastian reversed the "no WOBL knob"
  decision on 2026-10-07. In his words now: *"Wobble ist ja schon fertig als
  Parameter für den Reverb, der Knob muss nur wieder richtig verdrahtet
  werden."*

## 2. Decided behaviour (Bastian, 2026-10-18)

### 2.1 ROOT

- One small knob per deck, `ROOT_A` and `ROOT_B`, independent of each other.
  SCALE stays one global control.
- **12 zones, C at the left stop, B (German H) at the right stop, chromatic in
  between.** Bastian first wanted C at both ends with the right one an octave up;
  that conflicts with the next point (a key change does not move the register,
  so "an octave up" cannot exist), and he chose the 12-zone C..B layout.
- **Turning ROOT keeps the running melody as close as possible to where it is**
  ("lieber so nah wie möglich an der aktuellen Melodie"). The pitch value stays
  where it is and only the scale grid moves: each note snaps to the nearest note
  of the new key. This is the quantizer's existing `set_root()` semantics. No
  transpose of the running melody, nothing is regenerated by the turn.
- **A song generated after the turn starts from the new root** (Bastian:
  "wenn ein Song neu generiert wird, dann sollte die normale Song-Mechanik vom
  neuen Grundton ausgehen"). He chose the **relative** reading: a song generated
  in D is the song the generator would have made in C, moved by the distance
  C→D. Concretely, each note deck carries a *song offset* in semitones, latched
  from its root at every full rebuild of the phrase and added to the pitch
  before quantizing. The offset is the root folded to the nearest signed
  distance from C, so the register stays near where TUNE puts it:
  C..F# → 0..+6, G..B → −5..−1. *(F# → +6 rather than −6 is my call.)*
  At C the offset is 0, so today's songs are unchanged.
- **Why relative and not "centre on the tonic"** (read from the code, not
  probed): the phrase generator pulls toward lane value 0
  (`engine/mod/lane.cpp:10`, `phrase_gen.h:47-58`), and lane 0 lands at the
  PITCH base 0.5 plus TUNE (`part.cpp:167-168`), i.e. semitone 18 + (TUNE−0.5)·36.
  The init patch's TUNE_A 0.500 and TUNE_B 0.175 (`gen_panel.py:804`, `:848`)
  put both decks' centre near F# — so the C song is not centred on C today
  either. Bastian rejected the absolute reading because it would move the init
  patch's centre from F# to C.
- **When a "new song" happens** (read from the code): a full rebuild of
  pattern A in `ModLane::_apply_pending_song_work()` (`lane.cpp:313-328`),
  raised by a SONG rung change (`control_law.h:840-841` → `new_phrase`), a
  FORM change, a STEPS length change, or entering STEP. It applies at the next
  phrase wrap, together with a brand-new melody, so the offset jump is never
  heard on an old melody. Partial RENEW renewals do not re-latch the offset.
  *(My call: an offset change mid-song would transpose half a song.)*
- Boots at C on both decks with offset 0, so the factory patch sounds exactly
  as today.

### 2.2 WOBL

- One small knob in the ROOM group wired to the existing `P_REV_MOD` /
  `set_reverb_mod()`, replacing the constant.
- Boots at **0.15**, the constant it has today, so the factory patch does not
  move. (Bastian's original by-ear range was "wobbel fest auf .1 - .2".)

### 2.3 Both VCV modules

Bastian answered "ok" to adding the three knobs to the big `Fireflow` module as
well. `FireflowHW` and the firmware already have the pots on the plate.

## 3. Measured and read facts the design rests on

**Measured (probe, 2026-10-18).** `Quantizer` alone, steady state (64 calls
after setup, `init(48000, 96)`, fresh object per input point), input swept
0..36 semitones in 0.01 steps, root 1..11 against root 0. Largest distance a
note moves on a key change:

| Scales | max shift | mean shift |
|---|---|---|
| Aeolian, Dorian, Mixolydian, Lydian, Phrygian | 1 semitone | 0.53 |
| Whole tone | 1 (even roots change nothing: same scale) | 0.55 |
| Minor pent, Major pent, Hijaz, Harmonic minor | 2 | 0.65–0.84 |
| Hirajoshi, Pygmy, Kumoi | 3 | 1.01–1.16 |

The same probe printed `root 12 vs root 0: max |d| = 0.000` (Dorian): the root
is taken modulo 12, which is why a right-end "C an octave up" was not possible
in this semantics.

**Measured (second probe, same setup).** The song offset of §2.1 relies on the
quantizer being translation-exact: `quantize(x + d)` in key `d` equals
`quantize(x)` in C plus `d`. Swept for all 13 scales, d ∈ {−5, −1, +1, +2, +6},
x 6..30 in 0.01 steps: exact everywhere except where the shifted note would
leave 0..36 — e.g. Hirajoshi, d = +6, x = 29.01..: wanted 37, got 33, the
nearest in-range note. 100 such points per pentatonic with large gaps (of
~12 000), 0 for the seven-note scales. So at the top and bottom of the
three-octave span an offset song folds back onto the nearest in-range note;
nowhere else does it differ from the C song.

**Read from the code (not probed).**

- The engine is already per deck: `Instrument::set_root(int p, int semis)`
  (`engine/instrument.h:197`) sets `_parts[p].quant()`. Only `apply_param()`
  (`engine/param_table.h:162`, sets both) and the render host
  (`host/render/scenario.cpp:138`) call it. Neither host nor the firmware does.
- Pitch is re-quantized every control tick from the live lane value
  (`engine/parts/part.cpp:286`), and the comment above it records that a
  sounding SYNTH note follows a mask change. So a ROOT turn is heard at once.
- While PULL's gravity is on, the quantizer ignores the root (`quantizer.h:138`,
  `root = _grav_on ? 0 : _root`): the neighbour's absolute harmony wins, as it
  already does over the scale.
- The chord layer (COLOR) reads `_quant.root_semis()` (`part.cpp:206`, `:428`,
  `:551`), so chords follow the deck's key.
- WOBL's constant lives at `control/control_law.h:936`
  (`inst.set_reverb_mod(0.15f)`) and in `bench/audition/init_patch.cpp:226`.

## 4. Goals

1. `ROOT_A`, `ROOT_B` and `REV_MOD` are panel parameters (ffctl ids), driven by
   the shared control law in VCV and in the firmware.
2. Turning ROOT on deck A changes deck A's key and nothing on deck B, and vice
   versa — **with PULL off**. PULL is a cross-deck feature by definition: a
   pulled deck follows its neighbour's sounding chord, which is built from the
   neighbour's root (`part.cpp:206`), so under PULL ROOT_A legitimately moves
   deck B. That is accepted, not a defect. *(My call.)*
3. WOBL's knob drives `set_reverb_mod()` over its full 0..1 range.
4. The factory init patch sounds unchanged: ROOT_A = ROOT_B = 0 (C),
   REV_MOD = 0.15.
5. On `FireflowHW` and the Rev A firmware the three pots stop being reserved:
   they draw real knobs, scan into real ids, and the panel-map row comments no
   longer say "reserved".
6. The big `Fireflow` module gets the three knobs too.
7. A song generated on a note deck after a ROOT change relates to the new key
   exactly as it would have related to C: same phrase, shifted by the folded
   offset of §2.1.

## 5. Non-goals and anti-goals

- **The turn is not a transpose.** A ROOT turn that shifts the *running*
  melody's register or keeps its exact shape is the wrong feature (Bastian
  chose "as close as possible"). Only the next generated song is offset.
- **No re-generation triggered by ROOT itself.** Turning ROOT does not raise
  `new_pending`; the offset waits for the next rebuild the player causes.
- **Not "centre on the tonic".** The absolute reading (new songs circle the
  root nearest TUNE) was rejected: it changes the init patch at C.
- **Not modulatable.** Neither ROOT nor WOBL gets a MOD-layer depth. ROOT joins
  SCALE, STEPS, SONG in the excluded faces; WOBL simply has no `MOD_CENTER_TARGETS`
  row. *(My call: SCALE, the closest relative, is excluded on purpose, and a WOBL
  depth would cost a MODD id and four count guards for a parameter nobody asked
  to modulate.)*
- **SMEAR stays a constant.** Only WOBL's decision was reversed; the
  by-ear-decisions entry keeps SMEAR's "no knob" rule.
- No change to the quantizer's root semantics, hysteresis or slew.
- No panel geometry change on `FireflowHW`: the three pots and their holes are
  already where the frozen plate has them. A hardware file edit is an
  anti-goal — the ordered Rev A board is not to be touched.

## 6. Constraints

- **Ids.** The panel/firmware pot ids are already `ROOT_A`, `ROOT_B` and
  `REV_MOD` (`hardware/reva/panel-map.json`). The ffctl params take exactly those
  names so no hardware file changes.
- **Per-deck pair pattern.** Copy `PAN_A`/`PAN_B`: appended in
  `APPENDED_PANEL_PARAMS` (`gen_panel.py`) ahead of the MOD layer, and read in the
  control law as `prm(p ? ROOT_B : ROOT_A)`, never through the stride helper —
  appended ids are not stride pairs (`control_law.h:586`, `:787-798`).
- **Stepped knob.** ROOT is a `KNOBI` with snap, range 0..11, like SCALE; the
  integer comes from the generated range table (`shell/controls.cpp:47-54`
  rounds, VCV's `snapEnabled` does the same) and the law calls `std::round`.
  *(My call: the house law, identical to SCALE, which rounds — so the C and B
  zones at the two stops are half as wide as the ten inner zones (1/22 of the
  travel against 1/11). Equal-width zones would need a second snap law in both
  hosts for one knob. The stops make the end zones easy to hit anyway.)*
- **VCV tooltip** shows the note name (C, C#, D … B) rather than the generic
  "Steps" label `Fireflow.cpp` gives an unknown KNOBI. *(My call: sharps, English
  names, matching SCALE's tooltip convention of English scale names.)*
- **Engine table.** `P_ROOT` is renamed in place to `P_ROOT_A` (deck A only) and
  `P_ROOT_B` is appended, so the positional vectors in
  `tests/param_impact_points.h` keep their positions. Inserting `P_ROOT_B` next
  to `P_ROOT_A` would shift those vectors silently. Position is not enough on
  its own: all four frozen points set `P_ROOT` to 6/6/8/4
  (`param_impact_points.h:87,153,222,288`), which today reaches both decks. The
  appended `P_ROOT_B` slot of each point is filled **by hand with that point's
  old `P_ROOT` value**, so every operating point stays where it was; a
  zero-filled slot would silently move deck B to C at every point and shift the
  whole deck-B impact baseline. *(My call.)*
- **Two toolchains, never mixed** (CLAUDE.md). Panels are generated, never
  hand-edited. VCV work finishes with `host/vcv/build-local.sh install`.
- English in every file; commit trailer per CLAUDE.md.

- **HW panel** (`gen_hw_panel.py`): the `RESERVED` dict and the three `HwOnly`

- **Firmware map** (`shell/gen_panel_map.py`): drop the three `RESERVED`

  `ffctl::kInitParamDefaults` automatically.
- **Engine table** (`engine/param_table.h`): the split of §6.
- **Engine, song offset** (`engine/parts/part.*`, `engine/mod/lane.*`): the

  C+d equals quantizing `x` in C, plus `d` — measured in §3, exact except where

## 8. Acceptance

1. A new test drives the control law with ROOT_A at each of 0..11 and ROOT_B at
   0 and asserts `set_root(PART_A, k)` and `set_root(PART_B, 0)`; and the mirror.
   It goes RED once against the unwired law.
2. A test proves WOBL reaches the engine: two control-law runs with REV_MOD 0
   and 1 give different `reverb_mod_for_test()` values, and the init patch gives
   0.15. RED once with the constant still in place.
3. `test_param_impact` covers `P_ROOT_A`/`P_ROOT_B` the way it covers every
   other id: both must move audio. That rig sums the decks and does not prove
   isolation; isolation is proved at the routing layer by test 1, and the engine
   side is `Instrument::set_root(p, …)` touching only `_parts[p]`
   (`instrument.h:197`). No separate per-deck render test. *(My call.)*
4. **Song offset.** Two identical parts (same seed, same patch, a note
   engine), one at root 0 and one at root 2, both fire `new_phrase` at the same
   tick; after the rebuild their quantized pitch differs by exactly 2 semitones
   on every tick where neither touches the 0/36 bound. A third case: turning
   the root without a rebuild leaves the offset at its old value (the running
   melody only snaps). And root 7 gives −5, root 6 gives +6. RED once with the
   offset unwired.
5. Full `ctest` (Release, `-E "^reva_"` unless `hardware/` changed — it must not)
   and both panel guards green; the shell firmware builds with `make images`.
6. `host/vcv/build-local.sh install`, then Bastian restarts Rack: three working
   knobs on both modules, ROOT tooltip shows the note.
7. Bastian's listening pass: the init patch sounds as before; turning ROOT
   changes the key without moving the running melody's register; the next SONG
   rung then brings a song that sits in the new key; WOBL wobbles.
8. Not a merge gate: the three pots on the real Rev A board are checked in P7
   bring-up with the other 70.
