# FLUX Mono Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Collapse FLUX's stereo `BbdEcho` pair to one line per deck, make the
resulting loss of echo width audible to the owner, and re-measure on hardware.

**Architecture:** `FxMem::echo` loses a dimension and the change cascades
through `Flux`, `PartFx`, `Part`, `Instrument` and every host. `Flux::process`
sums its input to mono, runs one line, and fans the result back out to both
channels. Nothing is added to recover the lost width — that is a separate,
later decision the owner makes by ear.

**Tech Stack:** C++17, doctest, CMake + Ninja + clang (desktop), a separate
Makefile build for `host/vcv`, ARM cross-toolchain + Python (bench), Daisy Seed.

**Design spec:** `docs/superpowers/specs/2026-07-29-flux-mono-design.md`.
Section references below (§3, §4, §6 …) point into it.

## READ THIS BEFORE TASK 1

**This round changes the sound on purpose.** Unlike the wrapper round that
preceded it, tests asserting on FLUX's output may legitimately need new
expected values — but only where the change in §3/§4 actually explains them.
A test that fails for a reason the spec does not predict is a real failure.
Never adjust an expected value without saying, in the report, which paragraph
of the spec accounts for the new number.

**Do not add panning, widening, or any stereo treatment.** The echo is
centred, deliberately, and the owner decides what to do about it after
listening. Adding "a small improvement" here destroys the experiment.

**Do not tune DRIVE, the compander, or anything in `bbd_tuning`** (§4). Mono
makes the saturator see the sum, so DRIVE will bite earlier. That is the
expected physics of one chip instead of two, and it is the owner's ear that
judges it — not this plan.

host and the tests changing in the same commit: the desktop build compiles all
of them together. That is why this task is larger than the others. It is one
mechanical cascade and the compiler names every site.

**Files:**
- Modify: `engine/fx/flux.h`, `engine/fx/flux.cpp`
- Modify: `engine/fx/part_fx.h`, `engine/fx/part_fx.cpp`
- Modify: `engine/parts/part.h`, `engine/parts/part.cpp`

  Tasks 3 and 4 consume these.

- [ ] **Step 1: `engine/fx/flux.h` — one echo, one buffer, one observer**

Replace the two members with one:

```cpp
    BbdEcho _echo;
```

Change the init declaration to take a single buffer:

```cpp
    void init(float sample_rate, float* buf);
```

Replace the two test observers with one. The pair existed to prove both
channels received the same coefficient; with one line there is nothing to
disagree:

```cpp
    // The feedback coefficient actually handed to the BbdEcho. The law is a
    // function of BOTH knobs (see the comment on apply_feedback) and is
    // assembled from a cached factor, so it is the one quantity in this class
    // whose correctness is numerical rather than audible -- a 1e-6 drift is
    // inaudible and still a bug.
    float feedback_coef_for_test() const { return _echo.Feedback(); }
```

Update the `kMaxSamples` comment: it says "Floats per channel the host must
provide". There is one channel now. Say "Floats the host must provide per
deck" and note that the count itself is unchanged — one line still holds
`kMaxStages / 2` cells and STAGES keeps its full range.

- [ ] **Step 2: `engine/fx/flux.cpp` — init, the three pushes, and process**

`Flux::init`'s opening becomes:

```cpp
void Flux::init(float sample_rate, float* buf) {
    _sw.init(sample_rate);
    _sr = sample_rate;
    _buf_ok = (buf != nullptr);
    if (!_buf_ok) return;
    _echo.Init(sample_rate, buf, kMaxSamples);
```

and its `_echo_l.SetStages(_stages_now); _echo_r.SetStages(_stages_now);` pair
becomes a single `_echo.SetStages(_stages_now);`. Everything else in `init`
is unchanged — in particular the `_drive_norm = -1.f`, `_stages_norm = -1.f`,
`_fb_scale` and `_time_mod_norm` resets all stay exactly as they are.

`apply_feedback` keeps its whole comment and becomes:

```cpp
    const float fb = _fb_norm * _fb_scale;
    _echo.SetFeedback(fb);
```

`set_drive` keeps its whole comment; its two `SetDrive` calls become one.

In `process`, the stage-change block's two `SetStages` calls become one, and
the two `Process` calls become the sum and fan-out:

```cpp
    // One line: the deck's stereo image is summed in and the single echo is
    // added back to both channels. 0.5 holds CENTRED material at exactly the
    // level the stereo pair gave it, which is the case every by-ear setting
    // in this instrument currently sits on; hard-panned material feeds the
    // echo 6 dB quieter than it used to. The power-preserving 1/sqrt(2) would
    // trade that for a 3 dB lift on the normal case, which is the worse
    // bargain (design spec 2026-07-29-flux-mono, section 3).
    const float e = _echo.Process(0.5f * (l + r) * send, hz);
```

then the gate block multiplies `e` in place of `el`/`er`, and the mix becomes:

```cpp
    const float wet = e * _mix_lin;
    l += wet;
    r += wet;
```

Keep every existing comment in `process` — the gate's long tolerance comment,
the clock-ceiling comment and the slew comments are all still true.
