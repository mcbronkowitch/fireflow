# WAVE Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a selectable four-voice, PPG-style wavetable engine whose allocation, FLOW/STEP, chord, CHOKE, filter, envelope, pan, sub, and VOICE-edit behavior stays identical to the existing synth while TIMBRE continuously scans a deterministic baked wavetable bank.

**Architecture:** Parameterize the existing `Voice` and `SynthEngine` over their oscillator type, preserving `Voice`/`SynthEngine` aliases for the analog oscillator and adding `WaveEngine = SynthEngineT<WtOsc>`. A committed 16-frame, 7-mip int16 bank is generated by a deterministic Python tool but compiled directly into every host; `WtOsc` performs frame interpolation, per-block position smoothing, and click-free mip transitions. `Part` owns the third production engine, while the renderer and the existing VCV ENG control expose it without adding a panel parameter.

**Tech Stack:** C++17, doctest, CMake/Ninja, Python 3 standard library, JSON render scenarios, VCV Rack 2 host code, Daisy Seed DWT benchmark harness.

## Global Constraints

- Work on branch `WAVE`.
- The shipping audio path remains heap-free and performs no `sin`, `pow`, `log2`, allocation, file I/O, or table generation.
- Preserve the current `MorphOsc` SYNTH render byte-for-byte. The baseline SHA-256 for `ctrl_identity.wav`, generated from commit `5ffa21a` in this workspace, is `659af928e1f273d9ba9619f9ad235844fec1c2277557ed81a0c2dc065c6eb336`.
- Keep the current engine IDs stable: `ENGINE_TEST_TONE = 0`, `ENGINE_SYNTH = 1`, `ENGINE_SAMPLER = 2`; add `ENGINE_WAVE = 3`.
- Keep four voices, `kCtrlInterval = 96`, round-robin/free-first allocation, oldest steal, FLOW drone/surface behavior, chord humanization, CHOKE hold, and deterministic seeding identical across SYNTH and WAVE.
- Keep the current `spky::SvfLp` voice filter. The older WAVE spec's `daisysp::Svf` wording predates the measured, bit-identical `SvfLp` replacement.
- Bake exactly 16 ordered frames and the mip lengths `1024, 512, 256, 128, 64, 32, 16`; commit generated int16 data so normal builds do not require Python.
- TIMBRE maps linearly to bank position `0..15`, clamps at the ends, and ramps to each control-rate target over exactly 96 audio samples.
- Each lookup uses linear phase interpolation inside each of two adjacent frames and linear frame interpolation between them. A mip change crossfades old to new over 96 samples.
- Keep one curated bank only. Do not add user/SD loading, bank selection, position envelopes, wrap modes, unison expansion, or new parameter IDs.
- Preserve VCV patch compatibility: saved ENG value `0` remains SYNTH and `1` remains SAMPLER; new value `2` selects WAVE.
- Do not infer a physical region from C++ `const`: the root firmware and bench both use `APP_TYPE = BOOT_SRAM`, so inspect the link map for `kBankSamples`. Prefer the linked SRAM image when it fits because existing measurements show scattered SDRAM reads are slower; do not add a copy mechanism without a separate measured design.
- WAVE is not complete until desktop tests, deterministic renders, VCV build checks, and the Daisy WAVE workload are recorded. The acceptance target is `wave_2x4` no slower than `synth_2x4`, with the full measured row below the 96-sample block budget.

```cpp
#include <cstdint>

namespace spky::wt {

inline constexpr int kFrameCount = 16;
inline constexpr int kMipCount = 7;
inline constexpr int kSamplesPerFrame = 2032;
inline constexpr int kTotalSamples = kFrameCount * kSamplesPerFrame;
extern const int kMipLength[kMipCount];

extern const int16_t kBankSamples[kTotalSamples];

inline const int16_t* table(int frame, int mip) {

}
```

```python
def symbolic_recipe(name):
    if name == "formant_ah":
        return formants((4.0, 1.5, 1.00), (10.0, 2.2, 0.62), (18.0, 3.0, 0.28))
    if name == "formant_oh":
        return formants((3.0, 1.3, 1.00), (7.0, 1.8, 0.70), (15.0, 2.8, 0.24))
    if name == "formant_uh":
        return formants((2.5, 1.2, 1.00), (6.0, 1.7, 0.56), (12.0, 2.5, 0.20))
    if name == "formant_eh":
        return formants((5.0, 1.5, 1.00), (12.0, 2.1, 0.72), (20.0, 3.2, 0.25))
    if name == "odd_hollow":
        return [(h, 1.0 / h, (h * 0.173) % 1.0) for h in range(1, 48, 2)]
    if name == "comb_3":
        return [(h, 0.8 / h, (h * 0.119) % 1.0) for h in range(1, 64) if h % 3 != 0]
    if name == "fifth_heavy":
        return [(h, (1.0 if h % 3 == 0 else 0.28) / h, (h * 0.071) % 1.0) for h in range(1, 64)]
    if name == "resonant_7":
        return [(h, (1.0 + 2.4 * math.exp(-0.5 * ((h - 7.0) / 1.3) ** 2)) / h,
                 (h * 0.137) % 1.0) for h in range(1, 64)]
    if name == "soft_saw":
        return [(h, 1.0 / (h ** 1.35), 0.0) for h in range(1, 128)]
    if name == "hard_saw":
        return [(h, 1.0 / h, 0.0) for h in range(1, 256)]
    if name == "spectral_junk":
        return [(h, (0.35 + ((h * 37) % 19) / 19.0) / math.sqrt(h),
                 ((h * 73) % 101) / 101.0) for h in range(1, 128) if h % 5 != 0]
    if name == "bit_organ":
        return [(h, 1.0 / math.sqrt(h), 0.25 if h % 4 == 0 else 0.0)
                for h in (1, 2, 4, 8, 16, 32, 48, 64, 96)]
    raise ValueError(name)
```

```cpp
static int crossings(WtOsc& o, int n) {
    int count = 0;
    float prev = o.process();
    for (int i = 1; i < n; ++i) {
        const float cur = o.process();
        if (prev <= 0.f && cur > 0.f) ++count;
        prev = cur;
```

Implement the rules exactly:

- `set_detune_cents` uses the same exact-value guard and control-rate `std::pow` as `MorphOsc`, then calls `set_freq(_freq)`.
- `_select_mip` uses `base_hz = _sr / 1024.f` and repeated doubling, not runtime `log2`; clamp to `0..6`.
- `set_freq` clamps to `0..0.45 * sample_rate`, updates `_inc`, and starts a new 96-sample mip crossfade only when the selected mip differs.
- `set_morph` clamps `m`, maps it to `m * 15`, and computes one linear step over 96 samples. Repeated identical targets are no-ops.
- `_read_frame` wraps the phase index inside the selected table, linearly interpolates the two phase samples, and returns int16-scale float.
- `_read_mip` maps position to `frame0=floor(position)` and `frame1=min(frame0+1,15)`, then linearly interpolates those frame reads.
- `process` advances/wraps phase, advances the position ramp, reads the current mip, and linearly crossfades from `_old_mip` while `_mip_xfade_remaining > 0`.
- Snap `_position` exactly to `_position_target` and `_old_mip` exactly to `_mip` on their final samples.
