# Bench evidence 2026-08-01 — tape FLUX and the frozen BBD-engine gate (`19f7560`)

Measured on the real Daisy Seed (STM32H750) on this desk, in one coherent
build/program/measure session. The measured image used profile `sweep`,
families `system sweep`, AXI execution layout, optimization `o2` (`-O2`), a
480 MHz core, 96-sample blocks, and D-cache + I-cache. The effective Make
identity was `BENCH_FAMILIES="system sweep" BENCH_ITCM_HOT=0
BENCH_OPTIMIZATION=o2`.

The exact README sequence was:

```text
python run.py --profile sweep --build-only
python run.py --profile sweep --no-build --program-qspi --build-only
python run.py --profile sweep --repeat 2
```

The QSPI helper programmed and byte-compared 65,024 bytes. Both runs reported
payload SHA-256
`ac234ac7f7540ed5cd0e8b8496b84fca8084a3b2c05cc513aa4dad8ed811fc27`
and device fingerprint
`1157cbd949e6c4100daa57d61d85e016d57e733f949f39e9a967add1e5e22dc8`.
The complete accepted capture is
`2026-08-01-19f7560-sweep-axi-o2.md` / `.csv` in this directory.

Every figure below is from that one binary and session. `pct_max`, not

## The BBD rows now measure one actual frozen engine case

`instrument_worst_bbd`, `instrument_worst_bbd_dtcm`, and
`inst_bbd_engine_worst` share `configure_inst_bbd_engine_worst` and
`proc_inst_bbd_frozen`. Both decks select `ENGINE_BBD`, shortest division,
clock-ceiling PITCH, maximum COLOR, FEEDBACK and MIX, live other-deck/audio
inputs, and STEP freeze. STEP is selected before the 200-block settle, and
both parts are retriggered on every settle and measured block so the gate
stays high. The setup asserts engine, division, actual clock and frozen state
for both decks after settling.

Tape FLUX is off in these engine rows. `fx_flux_sdram` is the separate stereo
tape-FLUX price, and the five RATE rows below move only its delay ladder.

bench's repeat noise. This is an observed result, not an assumption from the
new tape architecture.

## Scope of the result

Movement 3 establishes musical differentiation: tape FLUX has a flat cost
across its delay ladder while the part engine provides the bucket-brigade
instrument behavior. This session does **not** prove that movement 3 saved CPU
relative to a matched pre-movement build. No such cross-build saving is
claimed; the valid comparisons here are the same-build rows above.
