# Bench run 2026-07-24 — `7ab2e26`

Measured on a Daisy Seed (STM32H750). 480000000 Hz core clock, block size 96, dcache+icache, `-ffast-math -funroll-loops`. Block budget 960000 cycles.

## Verdict

**2x4 budget — go/no-go.** The full instrument at its worst case (8 voices, COLOR 4-note on both parts, all FX on, high diffusion, echo at max) costs **98 % of the block budget offline**, and **98 % measured inside a real audio callback**. The anchored figure is the one that decides. **Conclusion: the 2x4 architecture fits.** The anchored figure is under 100 % of the block budget.

**Cost per candidate, relative to one real spotymod voice.**

- `modal_voice` — 6.5x one real voice (44x a bare oscillator kernel)
- `string_voice` — 2.0x one real voice (14x a bare oscillator kernel)
- `resonator` — 5.9x one real voice (40x a bare oscillator kernel)
- `formant_osc` — 0.31x one real voice (2.1x a bare oscillator kernel)
- `vosim_osc` — 0.99x one real voice (6.8x a bare oscillator kernel)
- `harmonic_osc` — 0.51x one real voice (3.5x a bare oscillator kernel)
- `grainlet_osc` — 0.69x one real voice (4.7x a bare oscillator kernel)
- `z_osc` — 1.1x one real voice (7.3x a bare oscillator kernel)
- `variable_shape_osc` — 0.20x one real voice (1.4x a bare oscillator kernel)

**SRAM vs SDRAM.** The grain-read proxy (8 scattered interpolated stereo reads per sample, identical window in both regions) costs **5.3x** in SDRAM against SRAM. That is a bare access pattern, written before the sampler existed to stand in for it; the `sampler_win_*` pair below is the same contrast with the real engine around it. The Oliverb pair reads **1.3x**, and the shortened echo-style streaming walk **3.3x**.

**The texture deck.** Both parts on the sampler at its worst case — DENS 8, SIZE 0.05 (128-sample grains spawning every 16), MOTION 1 scattering reads over the whole 42 s record buffer, SCAN running, and instrument_worst's FX chain unchanged around it — costs **88 % of the block budget on the mean block and 109 % on the worst**, against **92 % / 98 %** for the same box with both parts on the synth. The mean is the cheaper of the two; the peak is not. **Conclusion: the texture deck fits on average and overruns on peaks.** The grain count itself is already capped (`kSpawnHeadroom`) and the ablations say the remainder is not a burst: with the MOTION and SIZE lanes quiet the cloud's per-block work is flat to 1 %, and the worst block is simply the ceiling's worth of grains plus the whole FX chain. Dropping either FLUX or the reverb from this patch brings it under 100 %; capping grains harder does not.

Solo, the same cloud is **18 %** mean / **21 %** peak, a musical setting (DENS 4, half-second grains, MOTION 0.5, playhead parked) is **10 %** mean, and running an overdub underneath the worst-case cloud costs **1.2x** its mean. SCAN driven at the VCV host's rate — every 16 samples, six times the engine's own control tick, the rate `SamplerEngine::set_scan`'s comment names as the one that matters — reads **1.0x** against the same cloud without it. With the whole engine around it the record buffer's region costs **1.2x** (`sampler_win_sdram` over `sampler_win_sram`, identical settings and identical 8192-frame content), well under the bare proxy's figure above: the scheduler, window, filter and normalization are all region-blind and dilute it.

**Task 8 parent attribution.** The `66d359d` values came from minimal
diagnostic binaries because the full parent bench did not link. The
diagnostics retained the exact parent engine code and exact Task 8 workload
setup/process: 96-sample blocks, 100 warmup blocks, then 1,000 blocks measured
with DWT. `lane_step_shape00` moved from 27,971 / 29,042 average/maximum cycles
to 28,040 / 29,050 (+0.247% / +0.028%), while `synth_1_voice` moved from
52,967 / 53,880 to 55,576 / 56,570 (+4.925% / +4.993%). The displayed parent
diagnostic average/maximum cycle values—not checksums—repeated exactly across
two captures. The current full captures differ slightly in cycles, while
their checksum comparison reported no drift. Both changes are within the
documented cross-build noise. The roughly 11,614-cycle lane value in an older
report predates intervening lane and workload-shuffle changes, so it is not a
valid `66d359d` diagnostic comparison.
